# SFDA Software-as-Medical-Device — CyMed Pathway

## When SFDA MDR applies

Any CyMed feature that meets SFDA MDR-1 definition of "medical device software":
- **Yes** — AI CDS (sepsis, deterioration, drug interaction alerts influencing clinical action)
- **Yes** — imaging AI triage (P0-11 add-on)
- **No** — patient portal · payments · scheduling · HR

## Classification

| CyMed feature | SFDA class | Rationale |
|---|---|---|
| Sepsis / NEWS2 / deterioration risk | Class B | Non-critical, supports clinical decision |
| Drug interaction alerts | Class A | Informational; clinician overrides |
| ICD-11 auto-coding | Class A | Administrative, not clinical |
| Imaging AI triage (stroke, ICH) | Class C | Critical, influences immediate care |
| Cardiac ML risk stratification (future) | Class C | Same |

## Documentation required

- **Software Bill of Materials (SBOM)** — auto-generated by CI pipeline
- **Risk management file** — ISO 14971 methodology
- **Clinical evaluation report** — external validation study for each Class B+ model
- **Instructions for use (IFU)** — in Arabic + English
- **Post-market surveillance plan** — annual performance report to SFDA
- **UDI (Unique Device Identifier)** — assigned per SW version

## Timeline

- Class A: self-declaration + registration (~6 weeks)
- Class B: technical file + notified body review (~4-6 months)
- Class C: full audit + clinical evaluation (~9-12 months)
