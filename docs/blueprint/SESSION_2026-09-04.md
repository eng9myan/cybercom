### 12c. Remaining PHI + EncryptedJSON

- **PHI free-text (104 CyMed columns total):** insurance_bridge
  (`clinical_justification`, `denial_reason`), `clinic/referrals.notes`,
  imaging orders `clinical_indication`, worklist `ai_findings_summary`,

  **Not encrypted (by design):** `clinic/referral_loop` +
  `ecosystem/referral_routing` — cross-tenant sharing channels where the
  receiving tenant must read the sender's `clinical_summary`.
- **`EncryptedJSON`** (`platform/common/fields.py`) — dict/list stored as an
  encrypted bytea, same per-tenant DEK as `EncryptedText` with a JSON codec.
  No blind index; a no-context read yields `json_default()` not a mask string;
  legacy `JSONField` rows decode transparently. `EncryptedText` refactored to
  expose `_to_plaintext`/`_from_plaintext`/`_masked_read_value`/`_is_masked_read`
  hooks. Applied to `ConsultationPlan.prescriptions`,
  `AnesthesiaRecord.agents_used`, `TeleReport.findings`.
- **`EncryptedText.pre_save` fix** — was mutating the instance attribute to
  ciphertext (broke reads right after `.create()`, e.g. `FHIRImagingService`).
  Now returns the ciphertext for Django to persist and leaves the instance in
  plaintext. Re-saving a value read masked raises instead of blanking the column.
- **Encoding fix** — 9 generated serializers had a stray CP-1252 `0x97` byte
  from Windows-default-codec batch writes; swapped for ASCII hyphen.
